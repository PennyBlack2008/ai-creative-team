## 검토와 수정 한도

비평은 필수 조건 누락·모순·사용 불가를 우선한다. 지적마다 ID, 결과물 위치, 위반 기준, 영향, 최소 수정안을 적는다. 중요한 지적은 최대 5개로 요약하되 발견한 필수 조건 위반을 숨기지 않는다. 문제가 없으면 “필수 수정 없음”으로 끝낸다. 점수나 결함을 억지로 만들지 않는다.

- 필수 수정: 승인 조건 위반, 근거 없는 핵심 주장, 사용할 수 없는 산출물. 해결 전 완료로 표시하지 않는다.
- 선택 개선: 취향·추가 아이디어. 기본적으로 보류하며 전달을 막지 않는다.
- 감산 검토: 지워도 완료 기준이 유지되는 반복·장식·충돌 지시를 제거한다. 필수 정보는 삭제하지 않는다.

총괄은 지적을 수용/이의/보류로 분류한다. 기준에 근거한 오류는 수용해 제작자 단계에서 수정한다. 이의는 근거를 비교하며 완료 조건이나 사용자 선호의 결정을 바꾸는 경우에만 사용자에게 올린다. 비평가 의견을 무조건 반영해 새 요구사항을 만들지 않는다.

최초 초안은 수정 0회다. 비평 또는 검증 결과로 제작 단계에 되돌아갈 때 자동 수정 횟수를 1 증가시킨다. 한 번에 여러 결함을 고쳐도 1회이며 비평과 검증은 같은 카운터를 공유한다. 자동 수정은 전체 작업당 최대 2회다. 이전 지적을 재검토하고 수정이 영향을 준 범위를 확인한다. 같은 필수 결함이 두 번의 연속 검토에서 남으면 한도가 남아도 조기 중단한다. 해결한 다른 결함과 혼동하지 않도록 지적 ID와 증상을 기록한다.

한도 소진 또는 반복 실패 시 현재 결과를 ‘수정 중단/미완료’로 제공하고 관찰 증상, 시도, 원인 가설(미확정 표시), 필요한 증거, 접근 변경안 최대 2개를 알린다. 자동으로 다시 만들지 않는다. 사용자가 특정 접근과 추가 수정 횟수에 동의하면 새 예산을 기록하고 재개한다. 중단 시 남은 이전 예산은 동결하며, 재개 후 허용 횟수는 새로 승인한 횟수만 적용한다. 기존 이력과 누적 횟수는 보존한다. 새 계획·단계 전환·새 채팅만으로 카운터를 초기화하지 않는다. 사용자 요청으로 별개 작업을 시작할 때만 새 작업 ID를 준다.
