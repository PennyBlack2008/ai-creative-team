# 수정 중단과 새 채팅 이어하기

설명용 예제입니다. 결함은 실제 영상에서 관찰한 것이 아닌 가상의 프롬프트 검토 상황입니다.

## 같은 결함이 남는 경우

| 시점 | 관찰 | 자동 수정 사용 | 다음 행동 |
|---|---|---|---|
| 최초 초안 v1 검토 | F1: 15초 조건인데 장면 합계 18초 | 0/2 | 필수 수정 수용 |
| 수정 v2 검토 | F1: 합계가 여전히 18초 | 1/2 | 같은 결함 연속 2회 → 조기 중단 |

예상 안내:

> 장면 시간 합계가 두 번 연속 조건을 충족하지 못해 자동 수정을 멈췄습니다. 현재 결과는 미완료입니다. 시간을 먼저 5+5+5초로 고정한 뒤 문구를 맞추는 접근을 제안합니다. 이 접근으로 추가 수정 1회를 진행할까요?

사용자가 “그 방법으로 한 번 더”라고 하면 추가 예산 +1, 누적 수정 이력을 기록합니다. AI가 사용자 대답을 대신 만들면 안 됩니다.

## 이어하기 카드 예시

```text
[함께만들기 이어하기 카드 / 형식 1 / 프롬프트 1.0.0]
작업 ID / 목표 / 요청 산출물: perfume-01 / 향수 광고 / 영상 생성 프롬프트
경로 / 관점 / 현재 단계 / 다음 행동: STANDARD / CREATIVE / 수정중단 / 추가 예산 응답 대기
계획 버전 / 산출물 버전: v1 / v2
대상 / 필수 조건 R1… / 금지사항: 제품 관심 고객 / R1 15초, R2 9:16, R3 사람·자막 없음 / 사람·자막
완료 기준과 현재 판정: R1 미충족, R2·R3 충족
선택한 방향 / 가정 / 미결정 질문: 흰 스튜디오 / 무상표 제품 / 추가 수정 1회 허용 여부
사용자 승인·위임: 흰 스튜디오 방향 승인 / 과거 대화
외부 실행 권한: 없음
자료·출처: 사용자 조건 / 실제 영상 없음
현재 결과물: v2 장면 구성 S1 0–6초, S2 6–12초, S3 12–18초. 생성 문구는 다시 첨부 필요.
자동 수정: 사용 1 / 예산 2 / 누적 1 / 추가 예산 승인 없음
지적 ID별 증상·연속 실패 횟수·수용/이의/보류·변경 이력: F1 합계 18초 / 2회 / 수용 / v2에서 미해결
미확인 사항 / 중단 이유: 실제 영상 미검증 / 같은 필수 결함 연속 2회
[/이어하기 카드]
```

새 채팅에서는 마스터 프롬프트와 이 카드를 함께 붙입니다. 수정 횟수를 0으로 되돌리거나, 누락된 생성 문구를 기억한다고 하면 실패입니다. 다음 사용자가 추가 예산을 승인하면 빠진 문구를 요청하거나 재작성 범위를 합의해 재개합니다. 카드만으로 외부 게시 권한이 생기지는 않습니다.

## 방향 변경은 실패와 구분

“흰 배경 대신 검은 배경으로 바꿔줘. 나머지는 유지해”는 명확한 변경 지시입니다. 계획 v2로 변경을 기록하고 그 부분만 반영합니다. 기존 초안의 결함으로 기록하지 않으며, 기존 자동 수정 이력도 지우지 않습니다. 수정중단 상태에서 이런 변경을 받으면 접근 변경과 추가 예산까지 허용한 것인지 구분합니다.
